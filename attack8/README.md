# attack8 — вывод начала расшифрованного образа через отладочный UART

RP2350 `enc_bootloader` собран в конфигурации Debug с выводом stdio через UART. При каждой загрузке он печатает первые 16 байт **расшифрованного** образа приложения в UART0 TX (GP0), прежде чем передать ему управление. Имея физический доступ к UART, можно прочитать эти байты без ключа

Отладочный вывод раскрывает первые 16 байт открытого текста, но не весь образ: в режиме CTR блоки гаммы независимы, поэтому утечка первого блока не раскрывает остальные. В исследованном образе эти байты образуют известную векторную таблицу Cortex-M и не содержат секретных данных

## Класс угрозы

Основной класс — CWE-1295 "Debug Messages Revealing Unnecessary Information": отладочный вывод оставлен в продакшн-сборке и печатает начало расшифрованного образа. Близкие классы — CWE-215 "Insertion of Sensitive Information Into Debugging Code" и CWE-200 "Exposure of Sensitive Information to an Unauthorized Actor"

Оценка CVSS 3.1: `AV:P/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N`, базовый балл 2.4 (Low)

## Какие данные выводятся

Загрузчик печатает `Post decryption image begins with`, а затем первые четыре 32-битных слова расшифрованного образа. Это векторная таблица ARM-приложения в SRAM:

| Слово | Значение     | Назначение                         |
| ----- | ------------ | ---------------------------------- |
| 0     | `0x20082000` | начальный SP, верх 520 КиБ SRAM    |
| 1     | `0x20000197` | Reset_Handler, адрес с Thumb-битом |
| 2     | `0x2000011b` | NMI_Handler                        |
| 3     | `0x2000011d` | HardFault_Handler                  |

Образ предназначен для исполнения из RAM по адресу `0x20000000` (`Chaining into 20000000`). Утечка подтверждает расположение приложения, но сама по себе не раскрывает секрет: первые 16 байт любого образа Cortex-M — фиксированная векторная таблица

## Проверка на физическом устройстве

Захват сделан с работающего RP2350 через UART с помощью второго RP2040, прошитого прошивкой Raspberry Pi debugprobe:

- `GP5` debugprobe (UART RX) ← `GP0` целевого RP2350 (UART TX)
- общая земля, уровни 3,3 В, формат 115200 8N1
- питание от целевой платы; сброс запускает однократный вывод загрузочного лога

Захваченные после `Pre decryption image begins with` слова побайтно совпадают с шифротекстом в `firmware_dump.bin` по смещению `0x80024`. Это подтверждает, что на устройстве запущен тот же образ, который анализировался офлайн

> [!NOTE]
> Загрузчик печатает только четыре слова, поэтому объём утечки ограничен 16 байтами. Для восстановления остальных данных нужен ключ из OTP, страницы которого закрыты на чтение, либо дамп SRAM через отладочный интерфейс, который отключён

## Артефакты

| Файл                         | Содержимое                                               |
| ---------------------------- | -------------------------------------------------------- |
| `out/boot_capture.txt`       | необработанный загрузочный лог UART с устройства         |
| `out/decrypted_app_head.bin` | первые 16 байт расшифрованного образа                    |
| `out/ciphertext_head.bin`    | первые 16 байт шифротекста для сверки с дампом           |
| `src/make_artifacts.py`      | создаёт бинарные артефакты из лога и сверяет их с дампом |

## Повторение проверки

```bash
python3 attack8/src/make_artifacts.py out/boot_capture.txt
```

Скрипт разбирает лог, сверяет слова до расшифровки с `firmware_dump.bin` и записывает два бинарных файла. Если шифротекст не совпадает с дампом, скрипт завершится с ошибкой
