# Демонстрационный ключ подписи RP2350

Приватный ключ secp256k1 для RAM-образа дампера OTP из эксперимента `attack11`. Апстримные инструменты ждут его в PEM без пароля, поэтому подпись выглядит как `picotool seal --sign <in> <out> private.pem`

Отпечаток для OTP — SHA-256 от 64 байт публичного ключа `X||Y`, без DER-обёртки и без префикса `0x04`. Он раскладывается по строкам `0x90–0x9f` слота `BOOTKEY1` как 16-битные little-endian слова, а старший байт каждой строки несёт ECC

| Параметр | Значение |
| --- | --- |
| отпечаток `BOOTKEY1` | `d047e66f32071fe9dbf974cc4d6dea57d6afabd441af751c01f3fcb9a7352e14` |
| публичный ключ `X||Y` | `be4e42e5cd351b0353d77fada7a2ba52158234583ef4f690a91a8d96053d6565fb31e1737dfda19d7dccf275c1e40375bcbc8cc37428de35b57730ce48e5ab71` |
| sha256 файла `private.pem` | `920a55ba301a4f593209544d86c3940267056d396309b5032c8561d3d19eac72` |
| кривая | `secp256k1` |

Отпечаток воспроизводится одной командой:

```sh
openssl ec -in private.pem -pubout -outform DER 2>/dev/null | tail -c 64 | sha256sum
```

Раскладку на реальных данных проверяет вендорский ключ: `picotool info -a firmware_dump.bin` печатает его как `8B2316D50D3BA117…D0192C56593824CB`, SHA-256 от этих 64 байт даёт `0492a8cb5941b8bd3e2ae960ec642de339c99cbb9feb85fd23790d60923b2cea`, и это побайтово равно строкам `0x80–0x8f` живого OTP

> [!CAUTION]
> Ключ — секрет: после записи отпечатка в OTP он становится корнем доверия, и каждый, у кого есть этот файл, подпишет образ, который устройство примет. Репозиторий приватный, но если он станет публичным или его расшарят, слот `BOOTKEY1` надо считать скомпрометированным: свободные слоты 2 и 3 принимают новый ключ, а старый отзывается через `KEY_INVALID`

На устройстве пока ничего не записано: отпечаток в OTP не залит, дампер не загружался
