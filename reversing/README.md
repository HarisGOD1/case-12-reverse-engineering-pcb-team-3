# Выделение программы и декомпиляция

Из [полного дампа](../artifacts/backup_full.bin) RP2040 выделена кодовая часть прошивки и импортирована в Ghidra. Получение дампа с платы описано в [векторе 0](../attack0/README.md); результаты анализа шифрования и PIN — в [векторе 1](../attack1/README.md) и [векторе 8](../attack8/README.md)

## Карта образа

В Ghidra сырой бинарный файл импортирован для ARM Cortex-M0+ с базой XIP `0x10000000`. Объём флеш-памяти — `0x200000` байт; `memmap.txt` фиксирует экспортированную область

```text
0x000000–0x0000FF  boot2, загрузчик внешней флеш-памяти
0x000100–0x006FFF  таблица векторов, код и константы приложения
0x007000–0x0FFFFF  стёртая область 0xFF
0x100000–0x1AF5FF  шифрованные данные хранилища
0x1AF600–0x1FFFFF  стёртая область 0xFF
```

Начальный SP — `0x20042000`, в таблице векторов адрес обработчика сброса — `0x100001F7` (бит Thumb включён). CRC-32/MPEG-2 по первым `0xFC` байтам boot2 совпадает с записанным `0x7A4EB274`; другое значение от `zlib.crc32` вызвано различием параметров CRC и не доказывает подмену boot2

| Артефакт | Что содержит |
| --- | --- |
| [`program.bin`](program.bin) | boot2, приложение и константы, первые `0x7000` байт дампа |
| [`app.bin`](app.bin) | приложение от смещения `0x100`, база `0x10000100` |
| [`program_decompiled.c`](program_decompiled.c) | декомпилированные функции |
| [`program_summary.txt`](program_summary.txt) | инвентарь функций и строк |
| [`memmap.txt`](memmap.txt) | карта экспортированной области Ghidra |

## Разбор программы

[`scripts/DecompileAll.java`](scripts/DecompileAll.java) импортирует кодовую часть для `ARM:LE:32:Cortex` с базой `0x10000000` и декомпилирует функции; [`scripts/DumpMemoryMap.java`](scripts/DumpMemoryMap.java) экспортирует всю инициализированную область. Извлечение диапазона `program.bin` из сырого дампа — выделение кода, **не отдельное чтение прошивки с платы**

| Адрес | Функция | Роль |
| --- | --- | --- |
| `0x1000089c` | `main` | после проверки PIN запускает USB и цикл обслуживания |
| `0x10000ab0` | `board_gpio_init` | считывает PIN с энкодера до выхода из блокирующего цикла |
| `0x10000354` | `msc_read10_decrypt_storage` | расшифровывает сектора при USB-чтении |
| `0x1000053c` | `msc_write10_encrypt_storage` | шифрует сектора при USB-записи |
| `0x100008d4` | `tud_descriptor_string_cb` | отдаёт USB-строки, включая серийный номер `123456` |

USB-серийный номер `123456` не является PIN: эталон PIN извлекается из [таблицы сравнения](../attack8/README.md). До выхода из цикла проверки `tud_init` не вызывается, поэтому доступ через обычный USB-MSC до верного кода отсутствует; BOOTSEL — отдельный режим bootrom

## Проверка результатов

[`attack1/decrypt_storage.py`](../attack1/decrypt_storage.py) расшифровывает сохранённый дамп в FAT12, из которого [`artifacts/prepare.py`](../artifacts/prepare.py) извлекает `your_prize.zip` и проверяет CRC. [Эмуляторный стенд](../attack4/emulator-stand/README.md) запускает сам бинарь: верный PIN открывает проверочный цикл, неверный — нет
