## 3 Наброска

Вектор 5: Отсутствие инвалидации сессии и таймаута разблокировки (Sticky State)

- Механика в коде (FUN_1000089c & FUN_10000ab0):
  Флаг верного PIN устанавливается в _(uint8_t_)0x20002ED2 = 1 один раз внутри блокирующего цикла энкодера FUN_10000ab0. После этого управление возвращается в суперцикл main (FUN_1000089c), где до бесконечности крутится tud_task_ext + app_led_task.
- Уязвимость:
  В прошивке отсутствует обработчик отмонтирования накопителя, события USB SUSPEND, а также таймер неактивности (inactivity timeout). Если пользователь разблокировал сейф и отошёл от компьютера, токен остаётся полностью смонтированным и доступным для чтения/записи до физического вытаскивания из USB-порта.
- Классификация: CWE-613 (Insufficient Session Expiration).
- CVSS v3.1: CVSS:3.1/AV:P/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N (6.1 Medium).
  Вектор 6: Ошибки проверки границ LBA в msc_read10 / msc_write10
- Механика в коде (FUN_10000354, строки 281–286):
  if ((param_3 < 0x200) && (param_2 < 0x800)) {
  uVar3 = (uint)CARRY4(param_3, *(uint *)(&stack0x0000020c + DAT_100004ec));
  uVar2 = 0x800 - param_2 >> 0x17;
  if ((uVar3 <= uVar2) && ...
- Уязвимость:
  Проверка использует смешанную арифметику с переносными флагами CARRY4 и сдвигами >> 0x17 вместо прямого сравнения (LBA + BlockCount) <= MaxLBA. При передаче кастомных SCSI-пакетов с переполнением 32-битного целочисленного значения LBA или BlockCount можно обойти верхний предел проверки и спровоцировать чтение за пределами массива хранилища (Out-of-bounds Read в область Flash-кода 0x10000000).
- Классификация: CWE-190 (Integer Overflow or Wraparound), CWE-125 (Out-of-bounds Read).
- CVSS v3.1: CVSS:3.1/AV:P/AC:H/PR:N/UI:N/S:U/C:M/I:N/A:N (4.2 Medium).
  Вектор 8: Статический серийный номер USB и возможность спуфинга токена
- Механика в коде (FUN_100008d4, строки 543–584):
  Строковый дескриптор USB iSerialNumber зашит жестко в rodata по адресу 0x1000537c и равен "123456".
- Уязвимость:
  Токен не имеет уникального аппаратного идентификатора (хотя RP2040 имеет Unique Flash ID). Это позволяет злоумышленнику полностью сэмулировать USB-устройство на любом другом микроконтроллере (например, на Pico), вводя в заблуждение хостовые DLP-системы и СКУД, ориентирующиеся на серийные номера USB.
- Классификация: CWE-1390 (Weak Authentication of Device Identity), CWE-290 (Authentication Bypass by Spoofing).
- CVSS v3.1: CVSS:3.1/AV:P/AC:L/PR:N/UI:N/S:U/C:N/I:M/A:N (3.5 Low).---

## 4 Направления атак на PIN (Аутентификацию)

1. **Физический брутфорс (Physical Hardware Bruteforce):**
   - Прямая физическая эмуляция сигналов поворотного энкодера и кнопки через внешний микроконтроллер (например, Raspberry Pi Pico).
2. **Умный брутфорс через физический интерфейс (Timing Oracle Bruteforce):**
   - Использование тайминг-оракула в проверочном цикле `FUN_10000ab0`: на каждую верную позицию цифры прошивка делает задержку 50 мс (`FUN_1000239c(0x32)`). Это позволяет подобрать 4-значный PIN посимвольно всего за $\le 40$ попыток вместо 10 000.
3. **Симуляция (Эмуляция платы / Скриптовая симуляция):**
   - Эмуляция логики проверочного цикла (Python-симулятор `pin/pin_sim.py` или симуляция контроллера), подтвердившая однозначный PIN `3952`.
4. **Поиск пароля в исходнике / дампе (Static Signature Inspection):**
   - Прямое извлечение эталона PIN-кода из байтов `rodata` по адресу `0x100054FF` (`00 03 09 05 02` -> `3952`).
